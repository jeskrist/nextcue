# Architecture

> Keep this current. If the structure below no longer matches the repo, update it as part of your task (see Rules).

## Overview

NextCue is a Flutter app that plays a looping media playlist (mixed videos and images) hands-free — built for situations where the user doesn't want to touch the screen (practice, workouts, presentations, tutorial steps, etc.). The user picks up to 10 files once via the OS file picker; the app remembers them across launches and cycles through them automatically, with drag-to-reorder and swipe gestures for control.

## Top-level layout

| Path | Purpose |
|---|---|
| `lib/main.dart` | App entry point, theme, and `_StartupRouter` — loads the saved playlist and routes to `FileSelectionScreen` (+ `PlaylistPlayerScreen` on top if a playlist already exists). |
| `lib/models/` | Data model. `media_item.dart` defines `MediaItem` (video or image, with JSON (de)serialization for persistence). |
| `lib/services/` | App logic and persistence. `media_playlist_service.dart` owns loading/saving the playlist (`SharedPreferences`), importing picked files, generating video thumbnails, and cleanup of orphaned thumbnails. |
| `lib/screens/` | Top-level screens. `file_selection_screen.dart` — pick/reorder/remove playlist items (drag-reorder, swipe-to-delete). `playlist_player_screen.dart` — full-screen playback with swipe-between-items and overscroll-to-go-back gestures. |
| `lib/widgets/` | Reusable UI pieces used by the screens. `single_video_player_view.dart` (video playback controls/scrubbing), `single_image_viewer.dart` (timed image display), `duration_picker_sheet.dart` (bottom sheet to set per-image display duration). |
| `test/` | Widget/unit tests, one file per screen/widget/service/model (e.g. `playlist_player_test.dart`, `media_playlist_service_test.dart`). Flat structure, not nested — mirrors `lib/*/*.dart` by filename, not by subfolder. |
| `assets/` | Bundled images: `assets/icon/` (launcher icon source images) and `assets/splash/` (splash screen images). Regenerated into platform folders via `flutter_launcher_icons` / `flutter_native_splash`. |
| `android/`, `ios/`, `macos/`, `windows/`, `linux/`, `web/` | Platform scaffolding generated by `flutter create` plus icon/splash output. Rarely hand-edited — see Conventions. |
| `pubspec.yaml` | Dependencies and asset declarations. Comments next to each dependency explain what it's for. |

## Entry points for common tasks

- **New screen** → add to `lib/screens/`, wire navigation from `main.dart` (`_StartupRouter`) or from whichever screen should link to it.
- **New reusable UI piece** (used by more than one screen, or complex enough to isolate) → `lib/widgets/`.
- **Change to playlist persistence, import, or thumbnail logic** → `lib/services/media_playlist_service.dart`. This is the single source of truth for playlist state on disk.
- **Change to the media item's shape** (new field, new type) → `lib/models/media_item.dart`, then update `toJson`/`fromJson`/`copyWith`/`==`/`hashCode` together, and check `media_playlist_service.dart` for any place that constructs a `MediaItem`.
- **New dependency** → add to `pubspec.yaml` with a one-line comment explaining what it's for (matches existing style), then `flutter pub get`.
- **Icon/splash screen changes** → replace source images in `assets/icon/` or `assets/splash/`, then re-run `dart run flutter_launcher_icons` / `dart run flutter_native_splash:create` (writes into the platform folders — don't hand-edit those outputs).

## Data flow

On launch, `main.dart` asks `MediaPlaylistService.loadPlaylist()` to read the saved list from `SharedPreferences`, validate that each file still exists on disk (dropping + cleaning up thumbnails for any that don't), and migrate a legacy single-video entry if present. `FileSelectionScreen` is always the base of the nav stack; if a playlist exists, `PlaylistPlayerScreen` is pushed on top of it. Adding media goes through `MediaPlaylistService.importMediaFile()`, which detects video vs. image by extension, generates a thumbnail for videos (via `fc_native_video_thumbnail`) or defaults images to a 5s duration, and always references the original file path rather than copying it.

## Conventions worth knowing

- Original media files are **never copied** — only thumbnails live in app-private storage (`getApplicationDocumentsDirectory()/nextcue_media`). Deleting a playlist entry deletes its thumbnail only, never the source file.
- Platform folders (`android/`, `ios/`, etc.) are generated scaffolding; icon/splash assets inside them are regenerated by the `flutter_launcher_icons` / `flutter_native_splash` commands rather than edited directly.
- Tests live flat in `test/`, named after the file/feature they cover — not nested to mirror `lib/`'s subfolders.
- `pubspec.yaml` dependencies each carry an inline comment stating their purpose — keep that pattern when adding new ones.
